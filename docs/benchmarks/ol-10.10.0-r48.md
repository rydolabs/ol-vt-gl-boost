# OpenLayers 10.10.0 vs M5 R48 — controlled GPU benchmark (2026-10-24)

> **Historical experiment, not a measured performance claim for the current `main` release configuration.** These numbers were captured before the R64 folder refactor and must not be represented as steady-state FPS, pan/zoom responsiveness, or production speed.

## Reproducible evidence

- GitHub Actions: [M5 R48 RTX run #40092410654](https://github.com/nssang00/chatgpt-write-test/actions/runs/40092410654).
- Original `R48-pixel` [artifact #12560052843](https://github.com/nssang00/chatgpt-write-test/actions/runs/40092410654/artifacts/12560052843); artifact ZIP SHA-256: `cf509e46261802c560d9cd6d09f97cbd61069f16ad2b0303b4209114ae8a00c1`.
- Four raw `result.json` files in the archive: `ol_a`, `r45_a`, `r45_b`, `ol_b`. All report `pass=true`.
- Same NVIDIA GeForce RTX 5060 Ti, Windows Chrome / ANGLE D3D11, OpenLayers 10.10.0, 512×512 physical framebuffer, DPR1, 8/16/32 distinct Innsbruck MapLibre/OpenMapTiles XYZ12 MVT inputs (32 independently hashed tiles overall), 3 samples per arm/scene. PBF fixtures are preloaded; texture/network fetch is **not** in these cold timings.

## Metric and results

Measured `coldToCapturedFrameMs` (ms, **lower is better**): end-to-end test-harness cold render-to-frame capture with GPU completion (`gl.finish`), two animation frames, and RGBA8 capture. It is **not** identical to user-observed first-paint latency, sustained FPS, or total map initialization cost. Each entry is the median of **three** samples within that arm. A and B are separate ABBA order positions, *not* additional datasets.

| Distinct MVT sources | Stock OL 10.10.0 A / B (ms) | R48 CPU-first path A / B (ms) | Paired latency reduction A / B |
|---:|---:|---:|---:|
| 8 | 123.0 / 104.7 | 45.5 / 37.9 | 63.0% / 63.8% |
| 16 | 177.0 / 159.0 | 39.4 / 39.0 | 77.7% / 75.5% |
| 32 | 282.6 / 283.5 | 62.0 / 72.0 | 78.1% / 74.6% |

Latency reduction = `(OL_ms - R48_ms) / OL_ms × 100`; this is **not** a claim that throughput or FPS increased by the same percentage. Full median rows, raw sample values, and calculated percentages are in [`ol-10.10.0-r48-abba.csv`](./ol-10.10.0-r48-abba.csv).

### Configuration warning — especially important

The historical R48 R45-labeled arm used the **CPU-first / deferred Worker enabled** configuration: nested sample records record `r45.enabled=true` and completed `workerRows`, even though the legacy top-level `workerPoolMode` was `off`. First capture did *not* wait for Worker completion. This is **not** an OpenLayers vs current `Worker OFF` A/B test and **not** proof of the earlier always-Worker cold-start target.

The current `ol-vt-gl-boost` `main` branch retains **Worker default OFF**, R48 **CPU line-join fallback**, and reorganized R64 modules. R65 on physical RTX demonstrated **12/12 exact pixel/tile-oracle equality** and OL fallback after the refactor ([run #40296090427](https://github.com/nssang00/chatgpt-write-test/actions/runs/40296090427)), but **did not rerun the OL 10.10.0 performance comparison on the merged branch**.

For separate real OpenLayers UI **Worker OFF vs deferred Worker ON** comparisons, see [R59/R60 original PR evidence](https://github.com/nssang00/chatgpt-write-test/pull/23#issuecomment-6393622321): Worker ON did **not** establish a reliable input-latency or first-paint win, supporting the OFF default. That is a different comparator; do not combine it with the table above.

The R48 exact OL RGBA8 oracle passed its tested 12/12 comparisons after a CPU line-join fallback. Hardware-specific benchmark results do not guarantee a comparable improvement on other maps, drivers, styles, GPUs, zoom levels, or browsers. Production deployment remains unapproved.
