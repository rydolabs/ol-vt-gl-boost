# OL VT GL Boost

**CPU-first optimized WebGL vector-tile rendering path for OpenLayers.**

The repository keeps OpenLayers Map / View / VectorTileSource integration while providing a direct geometry-to-GPU pipeline, a strict CPU line-join fallback for pixel correctness, and an optional deferred Worker (default **OFF**). **Experimental: not production-approved.**

## Simplified API (R67 main)

`OLVectorTileBoost` composes the existing `DirectM5SceneBinding` and `WebGL1Backend` behind **one opt-in lifecycle object**. Unlike the old entrypoint, callers do not have to manually construct both components:

```js
import {OLVectorTileBoost} from './src/index.js';

// map: an already configured OL Map with supported VectorTile layers.
// canvas: a separately managed WebGL overlay (see runnable side-by-side example).
const boost = new OLVectorTileBoost({
  map, canvas,
  vectorTileOptions: {
    drawMode: 'style-pass', stableStyleIdentityCache: true,
    olLayerFboComposition: true, closedLineJoins: true
  },
  layerStyleResolver: layer => styles.get(layer),
  onError: ({error}) => { /* host-owned fail-closed fallback to stock OL */ }
});
boost.start({renderSync: false});
// ... after the host decides to restore stock OL:
boost.stop();
boost.destroy();
```

The API is **not a package release or production replacement**. The application must manage the overlay, supported layer types and actual stock-OL restoration. Deferred Worker remains **OFF unless explicitly opted in**. The tested legacy `DirectM5SceneBinding` entrypoint remains exported for compatibility. Source structure and verification: [R67 consolidation details](docs/R67_CORE_CONSOLIDATION.md).

## Usage example — stock OpenLayers vs OL VT GL Boost

A **runnable side-by-side example** is included: [examples/compare/index.html](examples/compare/index.html). It uses OpenLayers **10.10.0** on the left and the **same OpenLayers Map / View / VectorTileSource APIs** with the direct WebGL1 rendering pipeline on the right.

### Run locally (Node.js 22, fixture download requires network)

```bash
git clone https://github.com/rydolabs/ol-vt-gl-boost.git
cd ol-vt-gl-boost
npm ci                  # restore OL 10.10.0, exact npm dependencies and 2 preserved patches
npm run test:rtx:prepare   # download/check 32 fixed distinct PBF fixtures
npm run example:compare    # localhost-only, port 4173
```

Open **http://127.0.0.1:4173/examples/compare/**. Drag or zoom either map; both use **one shared View instance**, the same local PBF data and equivalent vector styles. The right-hand panel has a **Switch to stock OL** button to demonstrate explicit rollback after stopping the optimized scene.

**Original OpenLayers 10.10.0** — native WebGL vector-tile layer:

const view = new View({projection, center: [16384, 8192], resolution: 64});
const {layers: stockLayers} = makeLayers(); // OL VectorTileSource + WebGLVectorTileLayer

**OL VT GL Boost** — the same OL layer/source/view objects, plus a direct WebGL scene:

```js
import {DirectM5SceneBinding, WebGL1Backend} from '../../src/index.js';

const {layers: boostLayers, styles} = makeLayers();
const boostMap = new OLMap({target: null, layers: boostLayers, view, controls: []});
const canvas = document.getElementById('boost-canvas'); // 512×512 overlay, pointer-events:none
const backend = new WebGL1Backend(canvas, {contextAntialias: false});
const binding = new DirectM5SceneBinding({
  map: boostMap, backend, canvas,
  layerStyleResolver: layer => styles.get(layer),
  vectorTileOptions: {
    drawMode: 'style-pass', stableStyleIdentityCache: true,
    olLayerFboComposition: true, closedLineJoins: true,
    polygonInsideSegmentFastPath: true, polygonEarBBoxPrecheck: true
  }
  // deferredWorker is not enabled: Worker OFF is the stable default.
});
binding.start({renderSync: false});
boostMap.setTarget(document.getElementById('boost-map'));

// Application-initiated rollback to stock OL after stopping optimized drawing:
binding.stop();
canvas.style.display = 'none';
// Re-enable the underlying stock OL layer canvas via the host's CSS.
```

The excerpt relies on shared `makeLayers()` / projection / styling setup; see the [complete HTML](examples/compare/index.html) for a working definition and fallback button. The repository is currently **private as an npm package** (`"private": true`); these imports use checked-in source paths, not a published package.

## Performance vs stock OpenLayers 10.10.0

The following is an **historical R48 controlled RTX benchmark (2026-10-24)**, not a newly measured result for the merged R64 `main` branch.

| Different MVT sources | Stock OL 10.10.0 (A / B) | Optimized R48 CPU-first (A / B) | Captured-frame latency reduction (A / B) |
|---:|---:|---:|---:|
| **8** | 123.0 / 104.7 ms | 45.5 / 37.9 ms | **63.0% / 63.8%** |
| **16** | 177.0 / 159.0 ms | 39.4 / 39.0 ms | **77.7% / 75.5%** |
| **32** | 282.6 / 283.5 ms | 62.0 / 72.0 ms | **78.1% / 74.6%** |

**Test conditions:** NVIDIA GeForce RTX 5060 Ti, Windows Chrome / ANGLE D3D11, 512×512 RGBA8, DPR1; 8/16/32 distinct Innsbruck MapLibre/OpenMapTiles XYZ12 PBF fixtures; preloaded inputs (network/texture fetch excluded); A/B are paired ABBA order positions, with **3 samples per scene per arm**. Table values are per-arm medians of `coldToCapturedFrameMs` — the test harness's cold-to-GPU-completed **captured frame**, including `gl.finish`, two RAFs, and pixel readback. Lower is better. Reduction is `(OL time − R48 time) / OL time × 100`. **This is not sustained FPS, pure user-visible first paint, interactive latency, or a universal performance claim.**

**Important configuration caveat:** the R48 CPU-first experimental arm used the R45 **deferred Worker enabled** path (`r45.enabled=true`, although an older `workerPoolMode=off` field appears in the artifact); the CPU first frame did not wait for Worker completion. The current repository defaults to **Worker OFF**, so these percentages **do not establish its current default-mode advantage over OL 10.10.0**. Separate real-UI R59/R60 comparisons found no dependable advantage from enabling deferred Worker. R64/R65 validated post-refactor correctness, **not a fresh OL performance benchmark**.

**Evidence:** [R48 physical RTX workflow](https://github.com/nssang00/chatgpt-write-test/actions/runs/40092410654) · [original benchmark artifact #12560052843](https://github.com/nssang00/chatgpt-write-test/actions/runs/40092410654/artifacts/12560052843) · [full methodology and limitations](docs/benchmarks/ol-10.10.0-r48.md) · [source median/sample CSV](docs/benchmarks/ol-10.10.0-r48-abba.csv). ## Architecture

| Path | Responsibility |
|---|---|
| `src/ol/` | OpenLayers maps, layers, frames, tiles and lifecycle |
| `src/tile/` | Vector-tile geometry, clipping and encoding |
| `src/gl/` | WebGL1 backend, GPU resources, drawing |
| `src/optional/worker/` | Optional deferred Worker path (**OFF** by default) |
| `src/compat/` | Legacy renderer and compatibility entrypoints |
| `src/index.js` | Public module entrypoints |
